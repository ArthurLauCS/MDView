# 导出可分享的单文件文档

你的任务：把一篇带本地图片的 markdown 整理成一份**单独发出去就能读**的文档，同时不损坏原文。

## 处理规则

**删除**（这些在别人机器上一定打不开）：

- 图片引用指向本地文件：`![图](./我的笔记_img/架构草图.svg)`、`![图](../assets/a.png)`
- 行内 HTML 媒体里的本地路径：`<img src="file:///C:/...">`、`<video src="D:\...">`
- 指向本地文件的链接：`[设计文档](D:/work/spec.md)`、`[笔记](./另一篇.md)`
- 文首 frontmatter 里的编辑器私有字段（如 `mdview:` 那一行）

**保留**：

- 远程图片：`![图](https://example.com/a.png)`——对方能访问，路径不会失效
- `data:` 开头的内嵌图片——图片本身就在文档里，没有任何外部依赖
- 远程链接与锚点链接：`[Anthropic](https://www.anthropic.com)`、`[见上文](#小节)`
- 其余一切正文、列表、表格、引用

**绝不触碰**：

- 围栏代码块（三个反引号，或三个波浪线）内部的任何内容。那里的图片语法是**给人看的示例**，不是真的引用；改写它就是损坏示例。两种围栏要分别配对，不要跨着数。
- 用更长的围栏（四个反引号）包起来的代码块属于同一种情况，一样不许动。
- 行内代码 `` `![图](./a.png)` `` 里的内容，理由同上。

## 图片的两种处理，先问用户要哪种

1. **丢弃**：直接删掉整个图片引用，正文保持连贯。
2. **留占位**：保留 alt 文字，写成 `![架构草图](图片已移除)` 或 `> [图：架构草图]`，让读者知道这里原本有东西。

不要替用户决定。如果用户没说，按当前项目的设置走；设置也没有，就用占位并在交付时说明。

## 先预览，再写完

**在写出文件之前，把会被删掉的行逐条列给用户看**：行号、原文、删除原因。用户确认后再输出。

不要输出"已为你清理了若干处"这种含糊说法——用户需要知道具体少了什么。

## 不要做的事

- 不要用 markdown 解析器把文档重新渲染一遍再输出。重新序列化会重排格式、改掉列表符号、把作者的排版意图抹平。**逐行处理**，只改需要改的行。
- 不要动段落之间的空行、缩进、表格的管道符对齐。
- 不要在清理后的文档里插入"本文档由 XX 导出"之类的说明。

## 交付前自查

1. 代码块里的内容与原文逐字一致。
2. 每一条被删的行都能说清原因。
3. 清理后的文档里不存在绝对路径、盘符、`file://`。
4. 保留的远程链接与 `data:` 图片没有被动过。
