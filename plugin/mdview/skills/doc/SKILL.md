# 按文档文件夹格式写文档

你的任务：把文档写成一个**自带图片的文件夹**。这个文件夹拷到任何一台机器上，文档里的每张图都还在。

## 格式

```
我的笔记/
├── 我的笔记.md
└── 我的笔记_img/
    ├── 架构草图.svg
    └── 时序图.png
```

```markdown
![架构草图](./我的笔记_img/架构草图.svg)
```

三个名字必须一致：文件夹名、md 主文件名、`_img` 目录的前缀。`读书笔记/读书笔记.md` 配 `读书笔记/读书笔记_img/`。

- 文档没有图片时不建 `_img` 目录，但 md 仍然放在同名文件夹里。
- 用户指定了位置就建在那里；没指定就建在当前工作目录下。
- 用户让你往一份**已有的** md 里加图：图片放进它旁边的 `主文件名_img/`，不要搬动这份 md。
- 同名文件夹已经存在时不要覆盖，问用户是换名还是写进去。

## 图片模式

从用户的话里判断模式，判断不出来就按「尽量生成图片」。

### 不生成图片

用户说了「不要图片」「纯文字」「无图」之类的话时使用。

- 不建 `_img` 目录，文档里不出现任何图片语法。
- 不留「此处应有图」之类的占位。原本想用图表达的结构，改用表格、列表或围栏代码块里的字符图。

### 尽量生成图片

默认模式。凡是图比文字讲得清楚的地方都配图：流程、架构、层级、时序、状态变化、对比、数据趋势、界面布局。

每张图必须说明一件文字说不清的事。不为凑数配图，不配装饰图。

按图的性质选做法：

| 图的性质 | 做法 |
| :--- | :--- |
| 结构、流程、关系、示意 | 手写 SVG。这是默认做法，绝大多数图属于这一类 |
| 数据图表（数据点多、要求精确） | 写脚本用绘图库生成 SVG 或 PNG，只把图片存进 `_img`，脚本不留在文档文件夹里 |
| 真实界面、运行结果 | 有截图工具且目标能运行时实际截图，存为 PNG；否则画 SVG 线框图，并在图注里写明是示意 |
| 照片、插画、写实图像 | 当前会话有图像生成工具时用它生成并存为文件；没有就不配这张图，在交付说明里告诉用户这里缺一张什么图 |

拿不准一张复杂的图该怎么做时，先用 SVG 做出能表达意思的版本，再在交付时说明它可以换成什么。

## 三条禁止

1. **禁止绝对路径**。`C:\Users\...\shot.png`、`/home/me/...`、`file:///...` 不许出现在图片引用里。
2. **禁止 base64**。`![图](data:image/png;base64,...)` 让文档体积暴涨、diff 变成一堵墙。用户明确要求内嵌时才用，并说明这是例外。
3. **禁止把自己生成的图片放到远程**。不上传图床或任何第三方服务。引用别人已有的网络图片可以，但要知道它会失效。

也不要只描述不画：「这里应该有一张架构图」不算配图。

## 路径与命名

- 路径以 `./` 开头，分隔符一律用 `/`，Windows 上也一样。
- 文件名用「内容语义 + 扩展名」，可以用中文：`登录流程.svg`，不要 `image1.png`、`未命名.png`。
- 文件名不含空格、括号和 `# ? % : * " < > |`。需要分隔时用 `-`。
- 路径原样书写，不做 URL 编码。
- 同名文件已存在：内容相同就复用；内容不同就加后缀 `架构图-2.svg`。不覆盖已有文件，除非用户在这次对话里明确同意。
- 每张图写有意义的 alt 文字，说清这张图表达什么。

## 生成 SVG 时

- 写 `viewBox`，宽高写死，不依赖外部 CSS。
- `font-family` 以 CJK 字体收尾：`'PingFang SC', 'Microsoft YaHei UI', 'Noto Sans SC', sans-serif`，否则中文会变成方块。
- 不引用外部资源：不写 `<image href="http://...">`、外部字体、`@import`。图片必须能离线打开。
- 标签文字要短，框宽留足。文字溢出比没有标签更糟。
- 背景用实色，不要透明：文档可能在深色或浅色主题下显示。

## 写作

- 文首可以有 YAML front matter（`title`、`tags` 等），不是必须的。
- 一个文档一个 `#` 一级标题，层级不跳级。
- 代码块写语言标记。
- 围栏代码块和行内代码里出现的图片语法是给读者看的示例，不算引用，不需要对应文件。

## 交付前校验

写完后运行本技能目录下的校验脚本：

```bash
node scripts/check.mjs "<文档文件夹或 md 文件的路径>"
```

不生成图片模式加 `--no-images`。

脚本检查文件夹结构、每条图片路径是否相对且能找到文件、`_img` 里有没有没被引用的文件、SVG 是否自包含。有错误就修到通过为止，不要把没通过校验的文档交给用户。

交付时告诉用户：文档文件夹的路径、生成了几张图、有没有哪张图因为缺工具而没有配上。
